### [Mission 1] 작업 단위:
- 도구 · 용도: AI 에이전트를 활용하여 src/cart.js의 장바구니 핵심 기능을 구현하고, 코드 작성 및 설계 사항을 검토하는 데 사용함.

- 입력한 요청(프롬프트) 요약 — 목표 / 맥락 / 제약 / 검증 기준: 장바구니 기능인 getCart, addToCart, changeQuantity, removeItem을 순서대로 하나씩 구현하는 것이 목표였음. 외부 라이브러리를 사용하지 않고, 모든 에러를 AppError로 처리하며, 내부 데이터를 직접 반환하지 않고 복사본을 반환하도록 요청함. 또한 검사를 모두 통과한 경우에만 저장소를 수정하도록 하고, npm run test:m1을 통해 검증하도록 함.

- 에이전트가 제안한 계획에서 사람이 바꾼 것: 대화 내용만으로는 사람이 에이전트의 구현 계획을 직접 수정한 부분을 확인할 수 없음. 다만 수량 검사 순서, 판매 중지 상품의 처리 방식, maxAddable 계산 방식 등 세부 정책을 가정으로 반영함.

- 결과 — 테스트 실행 결과(통과 / 실패 수): 네 가지 장바구니 핵심 함수의 구현이 완료되었다고 에이전트가 보고함. 테스트 실행은 사용자에게 직접 확인하도록 안내했으므로 실제 통과 및 실패 개수는 확인되지 않음.

- 에이전트의 실수 · 환각 · 불필요한 변경 (있다면): 대화 내용에서 명확하게 확인된 실수나 불필요한 변경은 없음. 다만 maxAddable 계산 방식을 다르게 적용한 부분과 판매 중지 상품의 처리 정책이 요구사항 및 테스트 기준에 부합하는지 추가 확인이 필요함.

- 사람이 확인한 범위(diff 를 어디까지 읽었는가, 직접 실행한 것): 대화 내용에는 사람이 직접 확인한 diff 범위나 테스트 실행 여부가 기록되어 있지 않음. 에이전트는 src/cart.js 파일을 덮어쓴 후 npm run test:m1을 실행하도록 안내함.

- 고친 점 / 다음에 바꿀 프롬프트 규칙: 수량 검사 우선순위, 판매 중지 상품의 장바구니 처리 방식, addToCart와 changeQuantity의 재고 계산 기준을 구체적으로 명시할 필요가 있음. 다음 작업부터는 구현 전에 각 함수의 입력값, 예외 상황, 반환값 및 수락 기준을 프롬프트에 명확하게 작성하고, 구현 후에는 테스트 결과와 변경된 diff를 함께 요청할 것임.

- 재시도 횟수: 한번만에 작업 마무리.

### [Mission 2] 작업 단위:
- 도구 · 용도: AI 에이전트를 활용하여 src/order.js의 주문 관련 핵심 기능을 구현하고, 기존 장바구니 기능과 함께 테스트하는 데 사용함.

- 입력한 요청(프롬프트) 요약 — 목표 / 맥락 / 제약 / 검증 기준: 주문 관련 핵심 함수인 canTransition, changeStatus, createOrder를 구현하는 것이 목표였음. 배송지, 빈 장바구니, 재고 부족 등의 유효성 검사를 수행하고, 모든 조건이 충족된 경우에만 재고 차감과 주문 저장이 이루어지도록 요청함. 검증 기준은 M1과 M2 테스트를 모두 통과하는 것으로 설정함.

- 에이전트가 제안한 계획에서 사람이 바꾼 것: 대화 내용에서 사람이 에이전트의 구현 계획을 직접 수정한 부분은 확인되지 않음. 다만 검사와 데이터 변경을 분리하고, createOrder를 동기 함수로 유지하며, 주문 시점의 상품 정보를 스냅샷으로 저장하는 설계가 적용됨.

- 결과 — 테스트 실행 결과(통과 / 실패 수): M1 테스트 12개와 M2 테스트 9개, 총 21개 테스트가 모두 통과했다고 보고됨. 실패한 테스트는 0개임.

- 에이전트의 실수 · 환각 · 불필요한 변경 (있다면): 제공된 대화 내용에서 명확하게 확인된 실수나 불필요한 변경은 없음.

- 사람이 확인한 범위(diff 를 어디까지 읽었는가, 직접 실행한 것): 에이전트가 M1 및 M2 테스트 총 21개가 통과했다고 보고함. 다만 사람이 직접 diff를 확인한 범위와 테스트를 직접 실행했는지는 대화 내용에서 확인되지 않음.

- 고친 점 / 다음에 바꿀 프롬프트 규칙: 주문 생성 과정에서 유효성 검사와 실제 데이터 변경을 분리하도록 명시할 필요가 있음. 또한 주문 성공 시에만 재고를 차감하고 주문 번호를 증가시키도록 요청하며, 주문 시점의 상품 정보를 스냅샷으로 저장하도록 구체적으로 작성할 것임. 다음 작업에서도 상태 전이 조건과 예외 상황을 명확히 제시하고 기존 미션 테스트까지 함께 실행하도록 요청할 것임.
